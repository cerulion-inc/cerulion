# Upstream ROS 2 message signature manifest, GENERATED. Do not hand-edit
# the signature blocks; regenerate with ./scripts/refresh_upstream_msg_manifest.sh
# and review the diff. The `!source` / `!accept` / `!accept-fields` lines below ARE
# hand-authored — they are human judgements and a refresh preserves them verbatim.
# (`!not-vendored` was REMOVED: it only ever suppressed an orphan signature block,
# and since a refresh rebuilds the body from the vendored tree that block can never
# be re-emitted, so one refresh made every such line permanently inert. A legacy
# line now fails at parse rather than sitting there looking meaningful.)
#
# Gated by native_ros2_messages/tests/upstream_drift_test.rs. Each `=<pkg>/<Name>`
# block records the NORMALIZED upstream signature of a vendored message:
#   f <type> <name>        a field, in DECLARATION ORDER (order is layout)
#   c <type> <NAME>=<val>  a constant, sorted by name (position carries no meaning)
# Normalization is documented in that test's module docs; briefly: field types come
# from the real `parse_rosmsg`, same-package nested refs are qualified on both
# sides, and comments/whitespace are dropped.
#
# WHY: Cerulion resolves layout by schema hash over the field list. If our text
# disagrees with a stock robot's, the hashes disagree and `walk_by_hash` refuses at
# the hash gate before framing is consulted — the topic silently renders nothing.
# The other corpus tests diff the vendored tree against ITSELF, so they cannot see
# a self-consistent transcription error. This manifest is the external truth.

# ─── provenance: where each package's upstream truth was verified against ───
# ONE DISTRO PIN PER PACKAGE, pinned per https://github.com/ros/rosdistro
# `<distro>/distribution.yaml`. Of the 22 packages below, 20 carry a distro pin
# (19 Jazzy, and `control_msgs` LYRICAL because 13 of its 39 messages do not exist
# in Jazzy at all — see the waiver section for what that cost us) and 2 carry NO
# distro pin at all. "Jazzy" is the majority, NOT the whole corpus.
# `jazzy`   = the repo's jazzy branch, which IS its Jazzy release branch.
# `release` = the ros2-gbp release repo at the exact released tag (authoritative;
#             used for packages that have no branch for their distro).
# `UNVERIFIED` = no distro-pinned source exists for this package at all.
#
# MUTABILITY, stated because the gate's design leans on provenance being
# reviewable: only the 5 `release` pins name an IMMUTABLE tag. The other 17 name a
# moving branch (`@jazzy` x15, `@main` x2), so two refreshes months apart emit
# byte-identical `!source` lines over different upstream states. For those 17 the
# line records WHERE we looked, not WHEN — only this file's git history dates a
# branch-pinned signature.
#
# These lines are cross-checked against the refresh script's `clone` table by
# `upstream_drift_test.rs::refresh_script_clone_refs_match_the_manifest_source_pins`,
# so the two copies of each pin cannot drift apart silently.

# ─── accepted divergences ───
# Each line is a message whose vendored text deliberately does NOT match the
# recorded upstream signature. The gate FAILS if one of these stops diverging,
# and also if one names a message that is neither vendored nor in this manifest
# (so waivers can neither rot into dead weight nor lie in wait to pre-authorise
# a future divergence).
#
# TWO DIRECTIVES, DELIBERATELY SPELLED DIFFERENTLY:
#   !accept        <pkg/Name> <reason>  — waives the CONSTANT lines only. The
#                                         FIELD list is still compared, so a
#                                         wire-affecting divergence under this
#                                         directive still FAILS.
#   !accept-fields <pkg/Name> <reason>  — waives the FIELD list too. The only
#                                         directive that can silence the
#                                         wire-affecting class. Also required
#                                         for a message upstream does not have
#                                         at all, since absence compares
#                                         NOTHING, fields included.
#
# That split exists because the blanket form is what hid the original fork: reach
# for a distro pin before a waiver whenever an absence is really "we vendored a
# different distro". See the control_msgs note below for what it cost us once.
#
# control_msgs USED to carry FIFTEEN waivers here — 2 field-level divergences plus
# 13 messages that "exist only in Rolling, absent from Jazzy" — because the package
# was pinned to Jazzy (`release/jazzy/control_msgs/5.9.0-1`) while the corpus was
# actually vendored from a later distro. That was not a harmless bookkeeping gap:
# a waiver on absence tells this gate to compare NOTHING for that message, and
# `control_msgs/VDA5050State` was sitting behind one carrying `string last_node_id`
# where upstream declares `uint32`. A stock robot publishing the upstream layout
# had every frame dropped at the schema-hash gate, and the gate built to catch
# exactly that class could not see it.
#
# The fix is a DISTRO PIN, not more waivers: `control_msgs` now pins to
# `release/lyrical/control_msgs/6.10.0-1`, where all 39 vendored messages exist and
# are compared. All 15 waivers are GONE, and all 39 vendored files are byte-identical
# to that upstream release. Deleting the 13 Jazzy-less types was the alternative and
# was REJECTED by design: they are public API.
#
# RESIDUAL, RECORDED HERE BECAUSE THE PIN REMOVED THE ONLY OTHER TRACE OF IT:
# "byte-identical to upstream" above means to LYRICAL 6.10.0. Two of the 15 removed
# waivers were NOT absence waivers — they documented real, hash-affecting
# divergences against JAZZY's control_msgs 5.9.0, and this PR did not change either
# vendored file, so those divergences are still live against a Jazzy robot:
#   * control_msgs/PidState — Jazzy declares p_error/i_error/d_error/p_term/d_term/
#     i_max/i_min; we (with Lyrical) declare error/error_dot/i_term/p_gain/i_gain/
#     d_gain/output.
#   * control_msgs/SteeringControllerStatus — Jazzy names the field
#     linear_velocity_command; we (with Lyrical) name it traction_command.
# Field names are part of the hash recipe, so a stock ROS 2 JAZZY arm publishing
# either type hashes differently from us: on the rmw path `walk_by_hash` refuses at
# the hash gate and the topic renders nothing; on the `ros2 attach` RAW path our
# corpus is used to CDR-decode the robot's bytes, and PidState's differing field set
# misdecodes rather than refusing. This gate cannot flag it — it compares against
# the pinned distro, which is Lyrical by design.
# REMEDIATION when it bites: resolve the robot's schema FROM THE ROBOT rather than
# from our corpus (`cerulion ros2 attach`'s schema-resolution ladder — the
# wire `~/get_type_description` rung serves the robot's own .msg text, which is
# authoritative for whatever distro it runs). Vendoring both distros' spellings is
# not possible: one package, one pin, one hash per type.
#
# statistics_msgs/StatisticDataPoint: upstream declares the STATISTICS_DATA_TYPE_*
# constants in the sibling StatisticDataType.msg (which we also vendor, matching
# upstream). Ours ADDITIONALLY inlines them here. Constants never reach
# MessageSchema, so this cannot affect the wire; removing them would drop
# user-visible names for no wire benefit.
!accept statistics_msgs/StatisticDataPoint additionally inlines the STATISTICS_DATA_TYPE_* constants that upstream declares only in the sibling StatisticDataType.msg — constants do not reach the wire
